# 02. 초기 개발 기록 (보관)

> 이 문서는 초기 구현 결정을 설명하는 보관 기록이며 현재 제품 범위나 완료 단계를 정의하지 않는다. 현재 개발은 [전체 출시 제품 계획](03-final-product-plan.md)과 [실무용 완성품 전환 계획](08-production-completion-plan.md)의 단일 출시 기준을 따른다.

## 목적

프로토타입의 목적은 전문 영상 엔진 완성이 아니라 제품의 편집 흐름을 검증하는 것이다. 사용자가 미디어를 가져오고, 화면비를 선택하고, 타임라인에서 컷을 조작하는 전체 동선을 먼저 확인한다.

## P0 — GUI 프로토타입

구현 및 1차 검증 완료 — 2026-08-08.

### 범위

- 데스크톱 편집기 레이아웃
- 로컬 영상·음성·이미지 가져오기
- 가져온 미디어 미리보기
- 16:9, 9:16, 1:1 시퀀스 화면비 변경
- 비디오·오디오·자막 트랙 표현
- 클립 선택과 드래그 이동
- 재생 헤드 이동과 간이 재생
- 클립 분할·삭제
- 실행 취소·다시 실행
- 타임라인 확대·축소
- 데모용 AI 초벌 자막 생성
- 단축키 Space, S, Delete/Backspace, Ctrl/Cmd+Z

### 제외 범위

- 실제 여러 트랙의 합성 재생
- 프레임 정확한 디코딩
- FFmpeg 렌더링
- 음성 인식 모델 실행
- 트랜지션, 키프레임, 색보정
- 프로젝트 파일 저장

### 완료 조건

- `pnpm dev`로 프로토타입을 실행할 수 있다.
- `pnpm build`가 오류 없이 완료된다.
- 가로/세로/정사각형 캔버스가 즉시 전환된다.
- 타임라인의 핵심 조작이 UI 상태에 반영된다.
- 1280px 이상의 데스크톱 화면에서 패널이 겹치지 않는다.

### 1차 검증 결과

- TypeScript 타입 검사와 Vite production build 통과
- 16:9, 9:16, 1:1 캔버스 전환 확인
- 클립 드래그, 분할, 삭제, 실행 취소 확인
- 데모 자막 3개 생성 및 타임라인 반영 확인
- 로컬 브라우저 테스트에서 콘솔 오류 없음

## P1 — 작동하는 단일 트랙 편집기

Developer Preview 구현 완료 — 2026-08-08. 장시간·VFR 성능 승인 테스트는 Beta 항목으로 이관했다.

### 범위

- 프로젝트 생성·열기·자동 저장
- 실제 영상 디코딩과 프레임 정확한 탐색
- 단일 비디오 트랙 및 오디오 재생
- 썸네일·오디오 파형 캐시
- 브라우저 네이티브 디코딩과 썸네일·파형 캐시
- 컷, 트림, 분할, 리플 삭제
- H.264/AAC MP4 출력
- 출력 진행률과 취소

### 완료 조건

- 스마트폰 가변 프레임레이트 영상을 불러올 수 있다.
- 30분 프로젝트를 저장하고 다시 열어 같은 컷을 재현한다.
- 미리보기와 출력 결과의 컷 지점 차이가 1프레임 이내다.

### 구현 및 검증 결과

- Tauri 2 데스크톱 셸과 Windows 실행 파일을 구성했다.
- Mediabunny/WebCodecs로 MP4 메타데이터, 실제 프레임 미리보기, 썸네일, 파형, H.264/AAC MP4 출력을 구현했다.
- `.editweave.json` 저장·열기, 로컬 자동 저장과 최근 5개 체크포인트, 오프라인 미디어 재연결을 구현했다.
- 실제 CC0 MP4/MP3로 가져오기, 타임라인 추가, 2초 H.264/AAC 출력, 프로젝트 재열기를 검증했다.
- Mediabunny/WebCodecs로 960px·30fps H.264/AAC 편집 프록시를 실제 생성하고 원본/프록시 미리보기 전환과 원본 최종 출력을 검증했다.
- 프레임 패킷 최대 240개의 지속 시간 분산으로 VFR 가능성을 진단하며 CFR/VFR 합성 회귀 테스트를 추가했다.
- 프록시 변환 버퍼는 현재 메모리 기반이지만, Tauri 데스크톱 앱에서는 완성된 MP4를 앱 캐시에 저장하고 프로젝트 재열기 시 복원하며 개별 삭제할 수 있다. 브라우저 개발 모드는 세션 종료 시 사라진다.
- 실제 iPhone/Android VFR 소스의 1프레임 정확도, 30/60분 A/V 동기화, 1.5GB 초과 원본용 디스크 스트리밍 변환은 Beta 완료 조건으로 남아 있다.

## P2 — 한국어 AI 초벌 편집

Developer Preview 구현 완료 — 2026-08-08.

### 범위

- 로컬 또는 선택형 클라우드 음성 인식
- 단어 단위 타임코드와 화자 구분
- 대본에서 문장을 삭제해 타임라인 리플 편집
- 침묵, 군더더기, 반복 문장 제안
- 자동 자막과 스타일 프리셋
- 제안별 미리보기, 적용, 거절, 전체 되돌리기

### 완료 조건

- AI 적용 전후를 한 번에 비교할 수 있다.
- 대본 수정과 자막/클립의 연결이 유지된다.
- 사용자가 원본 미디어를 클라우드에 올리는지 명확히 선택할 수 있다.

### 구현 및 검증 결과

- Transformers.js Whisper tiny를 WebGPU/WASM으로 로컬 실행하는 음성 인식 경로를 구현했다. 원본은 업로드하지 않는다.
- SRT/VTT 가져오기와 SRT 내보내기, 대본 편집, 문장 단위 리플 삭제, 자막 트랙 반영을 구현했다.
- 군더더기·반복·파형 기반 무음 제안과 적용·거절·실행 취소를 구현했다.
- 한국어 SRT 5문장에서 군더더기·반복 2건 탐지, 적용 후 실행 취소 복원을 화면에서 검증했다.
- 실제 Whisper 모델 최초 다운로드를 포함한 장시간 음성 인식, 화자 분리, 단어 단위 강조는 Beta/V1 후속 항목이다.

## P3 — 롱폼에서 쇼츠 만들기

Developer Preview 구현 완료 — 2026-08-08.

### 범위

- 롱폼 시퀀스 복제 후 9:16 변환
- 하이라이트 후보와 제목 제안
- 인물 중심 자동 리프레임
- 강조 자막과 안전 영역
- 15초, 30초, 60초 버전 생성
- 여러 버전 일괄 출력

### 완료 조건

- 하나의 롱폼 프로젝트에서 원본을 복사하지 않고 쇼츠 시퀀스를 만든다.
- 자동 구도 결과를 클립별로 수정할 수 있다.
- 쇼츠 UI에 플랫폼 안전 영역이 표시된다.

### 구현 및 검증 결과

- 한 프로젝트 안에 원본과 여러 파생 시퀀스를 저장하고 상단 선택기로 전환하도록 확장했다.
- 대본 훅 점수를 이용해 15/30/60초 후보와 제목을 제안한다.
- 선택 구간만 비파괴 복제하고 9:16 세로 채우기 배율과 중앙 구도를 적용한다.
- 클립별 위치·크기를 인스펙터에서 다시 조정할 수 있고, 미리보기에 Shorts 안전 영역을 표시한다.
- 쇼츠 여러 개를 H.264/AAC MP4로 순차 일괄 출력하는 렌더 큐를 구현했다.
- 3개 파생 시퀀스 생성·원본 복귀 보존, 실제 MP4 기반 쇼츠 2개 일괄 출력을 화면에서 검증했다.
- 얼굴·화자 추적 자동 리프레임은 현재 중앙 자동 구도이며 V1 고급 기능으로 남아 있다.

## 검증 순서

1. 내부 기능 점검
2. 실제 편집자 3명에게 10분 분량 토킹헤드 편집 요청
3. 막힌 지점과 반복 클릭 기록
4. 기능 추가보다 작업 흐름 수정 우선
5. 60분 실제 프로젝트로 성능 검증
