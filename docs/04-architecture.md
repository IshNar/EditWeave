# 04. 기술 아키텍처

## 권장 스택

- UI: React + TypeScript
- 데스크톱 셸: Tauri
- 편집 코어: Rust
- 현재 미디어 입출력·렌더: Mediabunny + WebCodecs/Web Audio
- 확장 호환 계층: 선택형 FFmpeg 별도 작업 프로세스
- 선택적 NLE 기반: MLT 프레임워크 기술 검증
- GPU: Windows는 Media Foundation/D3D11 및 벤더 인코더, macOS는 VideoToolbox/Metal
- AI 작업: 독립 워커 프로세스 또는 로컬 서비스

React/Vite UI는 Tauri 2 데스크톱 셸에서 그대로 실행한다. H.264/AAC 공통 경로는 브라우저 네이티브 코덱을 사용해 배포 라이선스와 설치 용량을 단순화했다. WebCodecs가 지원하지 않거나 1.5GB를 넘는 데스크톱 원본은 원본 경로가 있을 때 시스템 FFmpeg 보조 프록시 명령으로 변환한다.

## 모듈 구조

```text
apps/
  desktop/       Tauri 셸과 OS 통합
  editor-ui/     React 편집 UI
crates/
  project/       프로젝트 스키마와 마이그레이션
  timeline/      트랙·클립·트림·실행 취소 명령
  playback/      프레임 요청과 A/V 동기화
  media/         미디어 분석, 프록시, 캐시
  render/        렌더 그래프와 작업 큐
workers/
  speech/        음성 인식과 화자 분리
  ai-edit/       초벌 컷과 하이라이트 제안
```

현재 전체 출시 소스는 위 경계를 `src/editor`, `src/media`, `src/ai`, `src/transcript`, `src/shorts`, `src/platform`, `src-tauri` 모듈로 표현한다. 장시간 렌더와 전문 코덱은 Rust 워커·별도 프로세스 경계로 확장한다.

## 핵심 데이터 규칙

- 현재 프로젝트 호환성을 위해 시간은 초 단위 수로 저장하고 프레임 편집 경계에서 FPS 기준으로 양자화한다. 장기 스키마 마이그레이션에서는 유리수 tick을 사용한다.
- 클립은 `timelineStart`, `sourceIn`, `duration`을 가진다.
- 화면비와 출력 해상도는 시퀀스 속성이다.
- 편집 동작은 명령으로 기록하여 실행 취소와 프로젝트 복구에 재사용한다.
- 프로젝트 파일에는 원본의 절대 경로만 믿지 않고 파일 크기·수정 시각·해시 단서를 함께 둔다.
- 생성형 AI 결과는 원본을 덮어쓰지 않고 새 에셋과 작업 메타데이터로 저장한다.

## 재생 구조

```text
UI 재생 헤드
  → 재생 스케줄러
  → 해당 시점의 활성 클립 계산
  → 디코더/프레임 캐시 요청
  → GPU 합성
  → 화면 표시

오디오 clock
  → master clock으로 사용
  → 비디오 프레임을 표시/드롭하여 동기화
```

현재 프로그램 모니터는 타임라인 재생 헤드에서 활성 클립을 계산하고 각 미디어 요소·Web Audio 그래프의 소스 시간을 동기화한다. 최종 출력은 동일한 클립 시간·변형·효과 모델을 프레임 타임스탬프별 Canvas/WebCodecs 합성에 사용한다. 다중 미디어 요소를 하나의 오디오 마스터 clock으로 묶는 전용 네이티브 재생 스케줄러와 GPU 셰이더 합성은 후속 고도화 항목이다.

## 프록시와 캐시

- 원본 분석 시 코덱, 프레임레이트, 색공간, 오디오 스트림을 기록한다.
- 썸네일·파형과 네이티브 디코더를 사용하고, 영상 패킷의 프레임 지속 시간 분산으로 VFR 가능성을 진단한다.
- 현재 편집 프록시는 Mediabunny/WebCodecs로 긴 변 960px, 고정 30fps H.264/AAC MP4를 만든다.
- Tauri 데스크톱에서는 변환 결과를 `StreamTarget`으로 `$APPCACHE/proxies/<project>/<asset>.mp4`에 직접 기록한다. WebCodecs 미지원 또는 1.5GB 초과 원본은 시스템 FFmpeg 보조 경로를 사용한다.
- 디스크 프록시 미리보기는 파일 전체를 JavaScript `File`로 다시 읽지 않고 제한된 Tauri asset protocol URL로 재생한다. 전사처럼 바이트 버퍼가 필요한 작업에서만 파일을 읽는다.
- 데스크톱의 256MB 초과 영상 원본은 Tauri 파일 범위 읽기로 분석·프록시 변환해 원본 전체 메모리 복사를 피한다. 브라우저 개발 모드는 BlobSource와 세션 프록시를 사용하며 1.5GB 제한을 유지한다.
- 썸네일과 파형은 별도 캐시로 두고 프로젝트 파일에 넣지 않는다.
- 원본과 프록시는 동일한 논리 타임라인을 공유한다.
- 최종 출력은 원본 디코딩을 우선하고, WebCodecs가 원본을 디코딩하지 못할 때만 호환 프록시를 사용한다.
- 사용자는 미디어 패널에서 캐시된 프록시를 개별 또는 프로젝트 전체로 삭제할 수 있고 원본은 삭제되지 않는다.
- 캐시는 지워도 재생성 가능해야 한다.

## 렌더 구조

- 타임라인을 불변 렌더 그래프로 변환한다.
- 미리보기와 최종 출력이 가능한 한 동일한 효과 파라미터를 사용한다.
- 프레임 인코딩은 WebCodecs 비동기 큐를 사용하고 오디오 믹스는 10초 청크로 메모리 상한을 둔다. 완전한 별도 렌더 프로세스 격리는 후속 안정화 항목이다.
- 진행률, 단계, 취소와 중단 상태를 로컬 작업 레코드로 저장하며 다음 실행에서 재시도를 안내한다.

## AI 구조

- 분석 작업과 편집 적용을 분리한다.
- AI 출력은 타임코드가 포함된 제안 목록이다.
- 적용 시 일반 타임라인 명령으로 변환한다.
- 모든 AI 동작은 한 번에 되돌릴 수 있는 명령 그룹으로 저장한다.
- 로컬 모델과 클라우드 모델이 같은 인터페이스를 사용한다.

## 플랫폼 및 배포

- 공통 코어가 OS API를 직접 호출하지 않도록 어댑터를 둔다.
- Windows와 macOS 빌드는 각각 해당 운영체제 CI에서 만든다.
- macOS 배포는 Developer ID 서명과 공증을 거친다.
- FFmpeg와 포함 코덱의 LGPL/GPL 및 특허 조건을 배포 방식별로 검토한다.

## 충돌 수집 경계

- React 렌더 오류, 전역 script 오류와 처리되지 않은 Promise는 최대 10개 로컬 큐에 저장하지만 사용자가 명시적으로 동의하기 전에는 네트워크로 보내지 않는다.
- 클라이언트는 `cutline-crash-v1` 이외의 프로젝트·미디어·렌더 데이터 필드를 만들지 않고, 로컬/네트워크 경로·URL query·이메일·UUID와 따옴표 안 동적 값을 큐 적재와 전송 시 제거한다.
- `services/crash-collector`는 Node.js 표준 라이브러리만 사용한다. 공개 POST 경로에서 크기·필드·시간·UUID·origin을 검증하고 속도 제한과 ID 중복 제거를 거쳐 단일 쓰기 큐로 날짜별 JSONL을 기록한다.
- 수집 서버는 IP·쿠키·요청 헤더를 영속화하지 않으며 보존 일수와 전체 용량을 모두 제한한다. 운영 배포는 비루트 컨테이너, 운영자 전용 암호화 볼륨과 HTTPS reverse proxy를 사용한다.

## 업데이트 배포 경계

- 개인 Ed25519 키는 오프라인 또는 보호된 릴리스 작업에만 사용한다. `release/create-update-manifest.mjs`가 플랫폼별 설치 파일 SHA-256과 운영 URL을 만들고 `release/sign-update-manifest.mjs`가 고정 canonical payload만 서명한다.
- `services/update-server`에는 공개 키와 key ID만 둔다. 시작 또는 SIGHUP reload 때 stable/beta·플랫폼 파일명, Ed25519 서명, 실제 artifact SHA-256·크기·OS 확장자를 모두 통과한 catalog만 원자 교체한다.
- 매니페스트는 64KB 이하·no-store·무리다이렉트로 제공하고 설치 파일은 압축 없이 최대 2GB의 immutable 전체/단일 Range 응답으로 제공한다. 요청 중 파일 크기·수정 시각이 달라지면 503으로 실패 폐쇄한다.
- 앱은 같은 공개 키를 renderer와 Rust 바이너리에 고정하고 플랫폼·SHA-256·OS 코드 서명을 다시 검사한다. 배포 서버 검증은 앱의 신뢰 검사를 대신하지 않는다.
