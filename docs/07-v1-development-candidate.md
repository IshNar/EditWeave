# 07. 전체 출시 개발 범위 기록

> 이 문서는 2026-08-08 당시 구현 범위를 보존한 개발 기록이다. 단계별 완료 후보로 사용하지 않으며 현재 전체 출시 기준은 [08. 실무용 완성품 전환 계획](08-production-completion-plan.md)이다.

## 상태 정의

2026-08-08 당시 구현된 범위를 기록한다. 패키지 버전과 관계없이 기능 공백은 전체 출시 소스에서 계속 개발하며, 발견된 문제는 `troubleshooting.md`에 증상·원인·해결·회귀 항목 순으로 누적한다.

## 구현된 개발 범위

### 편집 코어

- 여러 비디오·오디오·자막 트랙 생성, 삭제, 선택, 잠금, 표시, 음소거, 솔로
- 뒤에 추가, 재생 헤드 삽입, 구간 덮어쓰기
- 일반·리플·롤·슬립 트림, 분할, 그룹 이동·삭제, 링크·그룹, 시퀀스 마커
- 속도 변경, 역재생, 정지 프레임, 크로스페이드·검정/흰색 디졸브
- 위치·크기·회전·불투명도 키프레임과 보간

### 화면과 오디오

- 멀티 비디오 레이어 프로그램 미리보기 및 렌더 합성
- 노출·대비·채도·색온도·틴트·하이라이트·그림자와 내장 LUT
- 클립/트랙 게인, 팬, 페이드, 솔로, 피크 미터·클리핑 경고
- 모든 채널의 source-wide sample peak를 분석해 -1 dBFS로 맞추고 미리보기·프리 Aux·출력에 같은 gain을 쓰는 피크 정규화, 미리보기·Aux·출력에서 같은 임계값과 6 dB soft-open 곡선을 쓰는 노이즈 게이트, 음성 강조, 대화 구간 BGM 덕킹
- 활성 클립과 프리/포스트 Aux를 하나의 공유 역할 버스에 합산한 뒤 삽입 체인·gain·brickwall limiter·master tanh를 적용하는 프로그램 미리보기와, 같은 dB compressor/limiter transfer 함수를 쓰는 최종 PCM 믹스
- 공유 master의 soft clip 직전/직후 stereo tap에서 실제 L/R peak를 읽어 -60~0 dBFS와 1.5초 과부하 hold로 표시하는 프로그램 오디오 미터
- 미리보기 Web Audio와 최종 PCM이 동일한 주파수·Q·gain으로 처리하는 RBJ Biquad high-pass·3-band shelf/peaking EQ·2.4kHz 음성 강조와 청크 경계 연속 필터 state
- mono equal-power, stereo center unity/crossfeed와 Quad·5.0·5.1 speaker downmix를 구분해 미리보기 StereoPanner와 일치시키는 클립·트랙 pan 자동화
- 출력과 같은 source-time으로 부분 PCM을 역방향 재표본화하고 공유 clip/버스 DSP graph에 rolling 예약하는 가변 속도 역재생 오디오 미리보기
- 정·역방향 가변 속도에서 40ms grain·10ms hop과 ±6ms 상관 정렬로 음정을 유지하고, 50ms pre-roll로 미리보기/출력 청크 경계를 재현하는 공통 time-stretch PCM
- 10초 청크 단위 스테레오 오디오 합성으로 장시간 렌더 메모리 상한 제어

### 대본·쇼츠

- 로컬 Whisper 단어 타임코드, 문장 그룹화, 로컬 휴리스틱 화자 라벨과 수동 수정
- 고유명사·오인식 교정 사전, 기본/볼드/미니멀/가라오케 자막 프리셋
- 16:9, 9:16, 4:5, 1:1 캔버스
- 지원 환경에서 여러 프레임 얼굴 위치를 분석하고 쇼츠 변형 키프레임 생성
- 세로 안전 영역 표시와 큰 하단 자막 충돌 경고

### 미디어·프로젝트·출력

- 미디어 검색, 폴더, 태그, 타임라인 사용 여부
- 최근 5개 자동 저장 체크포인트를 UI에서 복원
- 데스크톱 디스크 스트리밍 프록시, 프로젝트 캐시 총량 표시·개별/전체 정리
- WebCodecs 미지원 또는 1.5GB 초과 원본을 위한 시스템 FFmpeg 보조 프록시
- H.264/H.265, 24/30/60fps, 비트레이트, 하드웨어/소프트웨어 인코더 선호 설정
- 멀티트랙 MP4, 쇼츠 일괄 출력, 렌더 중단 기록, FCPXML·CMX 3600 EDL
- Windows 개발/릴리스 실행 분리, macOS 실행 스크립트, Windows/macOS 빌드 CI
- 사용자가 누르는 업데이트 확인과 명시적 동의 후 충돌 보고

## 사용자 검증 순서

1. `run.bat`으로 최신 소스 앱을 열고 프로젝트 생성·자동 저장·버전 복원을 확인한다.
2. 실제 MP4/MOV/MP3/PNG를 가져와 검색·태그·프록시 생성·재실행 복원을 확인한다.
3. V2/A2/T2를 추가하고 삽입·덮어쓰기·네 가지 트림·링크·그룹·마커를 각각 확인한다.
4. 키프레임, 트랜지션, 색보정, LUT, 속도·역재생·정지 프레임을 미리보기와 출력에서 비교한다.
5. 트랙 솔로·팬과 클립 게인·페이드·정규화·노이즈 감소·음성 강조·덕킹을 확인한다.
6. Whisper 인식 후 화자명·교정 사전·단어 자막 프리셋을 확인한다.
7. 30초 쇼츠를 만들고 얼굴 중심 이동, 세로 안전 영역, 자막 충돌 경고를 확인한다.
8. H.264와 가능한 장비에서 H.265를 출력하고 FCPXML/EDL을 Premiere/Resolve/Final Cut에서 연다.
9. 렌더 중 앱을 종료한 뒤 재실행하여 중단 기록 안내를 확인한다.
10. `pnpm check`, `pnpm desktop:build`를 실행하고 새 패키지를 실제 Windows/macOS에서 설치한다.

## 외부 조건

- H.265와 하드웨어 인코딩 지원 여부는 OS·GPU·WebView의 WebCodecs 구현에 따른다.
- 전문 코덱 보조 프록시는 `ffmpeg` 실행 파일이 PATH에 있어야 한다.
- 얼굴 감지는 WebView가 `FaceDetector` API를 제공할 때 자동 추적점을 만들며, 미지원 환경에서는 중앙 리프레임과 수동 키프레임을 사용한다.
- macOS 서명·공증과 Windows 코드 서명은 각 개발자 인증서와 CI secret이 있어야 완료된다.
- 업데이트·충돌 서버는 `.env.example`의 URL을 운영 엔드포인트로 설정해야 활성화된다.
