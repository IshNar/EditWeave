# 08. 실무용 완성품 전환 계획

## 목표

Cutline을 화면 시연용 프로토타입이 아니라 유튜브 편집자가 실제 영상 파일을 가져와 롱폼과 쇼츠를 편집하고 결과물을 납품할 수 있는 Windows/macOS 데스크톱 제품으로 완성한다.

현재 상태 판정은 [10. 구현 근거 매트릭스](10-implementation-evidence-matrix.md)에서 소스 연결, 알려진 공백, 사용자 검증과 외부 출시 조건을 분리해 관리한다.

## 완료 판정 원칙

- 버튼과 화면만 존재하는 기능은 구현으로 계산하지 않는다.
- 미리보기와 최종 출력에 같은 편집 결과가 반영되어야 한다.
- 실제 원본 파일, 저장 프로젝트 재열기, 장시간 출력까지 한 흐름으로 이어져야 한다.
- 외부 서버·인증서·OS 코덱처럼 코드만으로 완료할 수 없는 조건은 제품 기능과 분리해 명시한다.
- 출시 차단 문제와 기능 공백을 모두 해결하기 전에는 전체 제품 완료로 표시하지 않는다.

## 현재 실제 구현 범위

### 미디어와 프로젝트

- 브라우저 파일 선택, HTML5 드롭, Tauri 네이티브 경로 드롭
- MIME 정보가 비어 있는 MP4/MOV/MKV/MXF/오디오/이미지의 확장자 판별
- 네이티브 다중 선택·경로 드롭·자동 재연결에서 성공 파일과 경로별 읽기 실패를 함께 수집해 성공 항목은 계속 분석하고 읽기 실패·미지원 형식의 개수와 첫 파일·원인을 표시. sourcePath+크기 또는 브라우저 File 이름+크기+수정 시각+MIME이 같은 원본은 중복 등록하지 않으며, 오프라인·분석 실패 항목은 기존 stable asset ID로 다시 분석
- 미디어 분석, 썸네일, 파형, VFR 진단, 프록시 생성·캐시
- FFprobe 사용 가능 시 스트림·포맷 TC/릴을 우선 읽고, 사용할 수 없거나 태그가 비어 있으면 Mediabunny가 해석한 MP4/MOV `udta/meta`, Matroska Tags, ID3, Vorbis, RIFF INFO의 원시 메타데이터 키·문자열·바이트에서 timecode/reel/tape 필드와 TC 패턴을 로컬 대체 판독
- FFprobe가 없거나 TC가 비어 있는 MOV/MP4에서 QuickTime atom을 범위 탐색하고 `tmcd` handler·sample description의 flags/time scale/frame duration/nominal fps, `stco`·`co64` chunk offset, `stsz` sample size와 첫 32-bit sample frame count를 직접 읽어 일반·29.97/59.94 드롭프레임 시작 TC와 source reference 릴 이름을 복원
- FFprobe의 color primaries·transfer·matrix·range, SMPTE ST 2086 mastering display 색좌표·최소/최대 휘도와 MaxCLL·MaxFALL 판독, PQ·HLG·BT.2020 광색역 분류 저장, HDR 대용량 프록시의 Hable Rec.709 톤매핑
- 데스크톱의 256MB 초과 영상 원본을 통째로 메모리에 복사하지 않는 파일 범위 읽기와 자동 편집 프록시
- 장시간 디스크 프록시를 JavaScript 메모리에 다시 복사하지 않는 앱 캐시 전용 asset protocol 미리보기
- 운영체제가 허용한 원본 경로 범위를 재실행 뒤 복원하는 Tauri persisted scope
- 빈 새 프로젝트, 프로젝트 저장·열기, 자동 저장 이력
- 상단 시퀀스 라이브러리에서 현재 캔버스·fps의 빈 일반 시퀀스 생성과 롱폼·쇼츠·중첩·멀티캠의 이름 변경·열기·복제·삭제. 복제는 시퀀스·트랙·클립·그룹·링크·키프레임·마스크·색상 노드·ADR 큐/테이크/컴프 ID를 새로 발급하고 미디어 asset ID와 중첩 의존 시퀀스만 공유한다. 삭제는 마지막 시퀀스, 다른 중첩 클립·파생 시퀀스·외부 ADR 큐/테이크 클립·병합 감사 기록·대기/진행 렌더·LAN 검토·열린 ADR 세션의 참조가 있으면 이유를 표시하고 차단하며, 허용된 삭제에서도 프로젝트 미디어와 디스크 원본은 유지한다.
- 저장소 용량 초과를 UI 오류로 복구하고 30초 간격 체크포인트를 남기는 자동 저장
- 같은 프로젝트의 자동 저장 전체 복원·과거 버전 분기에서는 stable asset ID의 현재 장비 File/Object URL·원본 경로·파형·프록시 핸들을 유지하고, 병합·외부 파일 열기는 이름·종류·확장자·크기·길이까지 같은 원본만 유지하며 바뀐 항목만 오프라인 재연결
- 저장된 데스크톱 원본 경로 자동 재연결 및 수동 동일 파일 재연결
- 사용 중인 원본 보호를 포함한 프로젝트 미디어 제거

### 편집과 합성

- 멀티트랙, 삽입·덮어쓰기, 이동·스냅·분할·일반/리플/롤/슬립/슬라이드 트림
- 삽입 편집은 삽입점 이후에 시작한 클립만 미는 근사 동작을 사용하지 않는다. 모든 잠금 해제 트랙에서 삽입점을 가로지르는 클립을 좌·우 소스 구간과 변형·속도·시각·오디오 자동화, 단어 자막에 맞춰 실제 분할하고 오른쪽 조각의 그룹·링크 ID를 함께 새로 발급한다. 이후 클립의 절대 ADR 컴프 범위와 트랙 믹스 키프레임, 마커·검토 코멘트·대본/단어·편집 제안 시간을 같은 길이만큼 이동하며 삽입점을 가로지르는 대본·제안 구간은 끝을 늘려 새 공백을 포함한다. 이후 ADR 큐·컴프·테이크 레인은 원자적으로 이동하고, ADR 큐/테이크 내부 또는 잠긴 ADR 레인 앞 삽입은 참조 손상을 막는 이유와 함께 차단한다. 이 전체 변경과 ADR 상태는 한 번의 Undo/Redo로 복원된다.
- 대본 구간 삭제와 AI 초벌편집 적용의 리플 삭제는 모든 잠금 해제 트랙에서 삭제 범위 앞·안·뒤·양쪽을 가로지르는 클립을 구분해 소스 시간, 속도/효과/오디오 자동화, 단어 자막과 내부 전환을 실제 재단하고 뒤쪽 클립·절대 ADR 컴프·트랙 자동화를 당긴다. 범위를 양쪽으로 가로지른 클립의 오른쪽 조각과 같은 그룹·링크의 후속 클립은 새 관계 ID를 공유해 왼쪽 조각과 독립된다. 대본 단어·제안 상태·마커/검토 코멘트·ADR 큐/컴프도 같은 범위 함수로 제거·재배치하며, LAN 검토 삭제 ID는 Undo/Redo에 따라 취소·재등록한다. ADR 큐/테이크와 겹치는 삭제, 누락/시간 불일치 참조, 이동해야 하는 잠긴 ADR 레인은 구체적인 원인과 함께 적용 전에 차단하고, 허용된 후속 ADR은 큐·컴프·테이크 레인을 원자적으로 당긴다.
- 리플 트림에서 클립 시작/끝을 안쪽으로 줄이면 선택 경계와 기존 경계 사이를 공통 리플 삭제로 제거해 선택 클립의 ID와 바깥 전환/fade를 보존하며 전체 시간 엔티티를 당긴다. 바깥으로 늘리면 기존 경계에 공통 timeline gap을 삽입하고 뒤 클립·트랙 자동화·대본/단어·제안·마커·ADR을 민 뒤 선택 클립의 소스 시간과 속도 곡선을 확장한다. 시작 확장은 기존 변형·시각·오디오 키프레임과 단어 자막의 로컬 시간을 추가 길이만큼 옮겨 원래 콘텐츠에 붙여두며, ADR 내부/누락/불일치/잠금 조건은 삽입·삭제와 같은 사전 검사로 차단한다.
- 덮어쓰기는 프로젝트 길이와 대본·마커 시간을 이동하지 않고 선택한 V/A 소스 대상 트랙의 범위만 교체한다. 범위와 교차한 일반 클립의 좌우 source offset, 속도·효과·오디오 자동화, 단어 자막, 전환/fade와 절대 comp 범위를 실제 재단하고 오른쪽 조각·후속 그룹/링크를 새 관계 ID로 분리한다. 대상 트랙의 ADR 큐/테이크와 조금이라도 겹치거나 cue→take→clip 참조가 손상된 범위는 원본 녹음을 덮지 않고 다른 트랙 지정 또는 ADR 정리를 안내한다.
- 일반·롤·슬립·슬라이드 트림은 클립의 현재 소비 소스 길이를 속도 곡선 적분으로 계산하고, 영상·오디오 자산의 실제 분석 길이와 중첩 시퀀스의 마지막 클립 끝을 원본 한계로 사용한다. 이미지·정지 프레임·자막·조정/생성 레이어는 시간 독립 소스로 구분한다. 일반 트림은 같은 편집점의 링크 V/A를 함께 재단하며 빈 간격과 원본 핸들까지만 확장한다. 슬립은 일정/가변 속도와 역재생 방향을 반영해 링크 클립의 source offset 허용 구간을 교집합으로 제한한다. 롤은 모든 링크 트랙의 맞닿은 양쪽 클립, 슬라이드는 모든 링크 트랙의 맞닿은 앞·선택·뒤 클립을 한 변경으로 처리하고 어느 한쪽이라도 원본 핸들·최소 50ms 길이·잠금·ADR 보호 조건을 위반하면 일부만 변경하지 않는다. 시작/끝 재단은 속도·변형·시각·오디오 자동화와 단어 자막을 같은 로컬 구간으로 슬라이스하고 바깥 전환/fade 길이를 새 클립 길이 안으로 제한한다.
- 리플 트림 확장은 선택 영상만 늘리고 같은 경계의 링크 오디오를 뒤로 미루지 않는다. 같은 링크 ID와 편집 경계를 공유하는 V/A 전체의 원본 핸들 교집합으로 확장량을 제한한 뒤 공통 timeline gap과 프로젝트 시간 메타데이터 이동을 적용하고 모든 링크 클립을 함께 확장한다. 정지 이미지·생성 레이어 이외의 원본 끝, 잠긴 링크 트랙 또는 ADR 테이크/컴프가 있으면 구체적인 이유를 표시하고 변경하지 않는다.
- 트랙 선택과 분리된 종류별 단일 `V/A/T` 소스 대상 지정. 트랙 머리글에서 대상을 켜면 같은 종류의 이전 대상을 원자적으로 해제하고 미디어·조정 레이어·모션 텍스트·중첩 결과를 해당 트랙으로 라우팅한다. 모든 대상을 명시적으로 끄면 해당 종류 추가를 오류 안내와 함께 차단하며, 대상·전체 해제 상태는 시퀀스별 프로젝트에 저장된다. 이전 프로젝트는 종류별 첫 잠금 해제 트랙을 기본 대상으로 승격하고, 새 트랙은 즉시 대상이 되며 대상 트랙 삭제 시 같은 종류의 잠금 해제 트랙으로 이전한다.
- 독립 소스 모니터의 인·아웃 지정과 선택 구간 3점 삽입, 내장 오디오 분리 후 독립 트림하는 J/L 컷
- 링크·그룹·마커, 일정 속도·키프레임 속도 램프·역재생·정지 프레임, 변형 키프레임과 위치 X/Y·크기·회전·불투명도를 직접 조절하는 인스펙터 값 그래프
- 속도 곡선을 적분한 공통 소스 시간 모델을 프로그램 미리보기·프레임 출력·오디오 출력·트림·분할·중첩·쇼츠 파생에 사용하고, FCPXML에는 시간 맵, EDL에는 램프 주석을 기록
- 재생 헤드는 `performance.now()` 기반 단일 monotonic 시계가 소스/프로그램 위치를 계산하고, 재생 중 외부 탐색이 1/120초보다 크면 현재 위치를 새 기준점으로 삼는다. 각 미디어는 정지·역재생·정지 프레임에서 1/240초 오차로 즉시 seek하고, 정방향 재생 중 오디오는 75ms 이상 drift를 재탐색하며 영상은 1프레임 이상 drift에 최대 ±2% 속도 보정 후 120ms 이상이면 재탐색한다. metadata 전 탐색은 마지막 요청을 보존해 준비 직후 적용한다.
- 역재생 오디오 미리보기는 전체 파일을 메모리에 올리지 않는다. 활성 구간 1.25초 전에 Mediabunny 범위 디코더를 준비하고, 출력과 같은 `clipSourceTime`으로 250ms PCM을 표본화해 최대 0.9초 앞까지 AudioContext에 예약한다. mono/stereo/Quad/5.0/5.1 downmix를 최종 출력과 공유하고 기존 clip gate·EQ·Dynamics·정규화·fade·pan·Aux·역할 버스에 연결한다. 탐색/ADR loop는 예약 source를 폐기하고 200ms lead로 재기준화하며, 세 번 연속 decoder underrun이면 무음으로 속이지 않고 프록시 사용 오류를 프로그램 화면에 표시한다.
- `속도 변경 시 음정 유지`는 새 클립과 기존 프로젝트에서 기본 활성화된다. 공통 PCM 처리기는 40ms Hann grain·10ms hop을 클립 시작점에 고정하고, 앞선 합성 파형과 ±6ms normalized cross-correlation이 가장 높은 source 위치를 골라 overlap-add한다. 각 렌더 요청 앞 50ms를 다시 합성한 뒤 버려 250ms 미리보기 청크와 2/10초 출력 청크 경계에서도 grain 선택을 재현한다. 정방향 속도 램프와 역재생은 이 처리기를 공유하고, 비활성화하면 기존 sample-time 재표본화로 속도에 따라 음정도 변한다.
- 속도 지점 사이를 선형·가속·감속·부드러운 곡선뿐 아니라 두 제어점을 직접 끄는 cubic Bézier 자유 곡선으로 편집하고, 곡선 적분값을 공통 소스 시간 모델에 사용하며 전체 램프를 `.cutline-speed.json` 팀 템플릿으로 저장·공유·다른 길이 클립에 비례 적용

### 오디오·자막·쇼츠

- 클립/트랙 게인·팬·페이드·솔로, 미리보기 StereoPanner, 하이패스·3밴드 EQ·컴프레서·리미터·음성 대역 강조. 노이즈 감소는 0~100%를 최대 0.035 amplitude 임계값으로 바꾸고 그 위 6 dB에서 부드럽게 열리는 공통 게이트 함수를 Web Audio WaveShaper 미리보기와 PCM 최종 출력·Aux·Delivery Guard에 공유하며, 별도 하이패스 설정을 임의 변경하지 않는다. 클립과 버스의 high-pass, 220Hz low shelf, 1.2kHz Q 0.75 peaking, 4.2kHz high shelf, 2.4kHz Q 0.8/+4.5dB 음성 강조는 Web Audio와 같은 RBJ Biquad 계수로 PCM 출력하며 필터 state를 렌더 청크 사이에 유지한다.
- 재생 헤드에 게인·팬 키프레임을 기록하고 선형·가속·감속·부드러운 보간을 미리보기·최종 믹스·중첩·쇼츠·분할/트림에서 공유하는 클립 오디오 자동화. 최종 PCM은 Web Audio StereoPanner 알고리즘과 같이 mono equal-power, stereo center unity와 방향별 반대 채널 crossfeed를 적용한다. Quad는 L/SL·R/SR을 0.5 합산하고 5.0/5.1은 C·SL/SR을 √0.5로 stereo downmix하며 LFE를 제외한 뒤 pan한다. 6채널 초과는 추가 rear/height 미보존을 Delivery Guard에서 경고한다.
- 타임라인 절대 시간에 트랙 음량·팬 키프레임을 기록하고, 자식·부모 중첩 트랙의 시간축을 합성해 미리보기·최종 출력·러드니스 예상에서 공유하는 트랙 자동화
- 최종 스테레오 믹스, 게이트, 음성 강조, 대화 구간 BGM 덕킹과 같은 처리 모델을 쓰는 출력. 피크 정규화는 원본의 모든 채널·모든 PCM sample에서 구한 source-wide sample peak를 프로젝트에 저장하고 -1 dBFS 목표(최대 ±24 dB)로 계산해 미리보기·프리 Aux·최종 출력·Delivery Guard에 같은 gain을 적용하며, 분석값이 없거나 무음이면 임의 증폭하지 않는다.
- 모든 오디오 트랙을 한 화면에서 조절하고 분석 파형으로 LUFS/True Peak를 빠르게 추정하며 상대 밸런스를 유지해 -14 LUFS에 맞추는 트랙 믹서
- 데스크톱 MP4 완성 뒤 FFmpeg EBU R128 필터로 통합 LUFS·LRA·True Peak를 실제 출력 파일에서 측정하고 단일·쇼츠 묶음 렌더 작업에 보존하는 납품 리포트
- 대화·음악·효과음·환경음 역할 버스의 게인·뮤트·솔로·안전 리미터, 클립별 최대 4개 프리/포스트 페이더 Aux 센드, 버스별 최대 6개 하이패스·3밴드 EQ·컴프레서·리미터 순차 삽입 체인의 우회·재정렬·삭제, 시퀀스별 저장·Undo. 프로그램 미리보기는 클립마다 버스를 복제하지 않고 하나의 AudioContext 안에서 역할별 summing input에 모든 활성 클립과 Aux를 먼저 합친 뒤 삽입 체인→버스 gain→brickwall ceiling→공유 master tanh 순서로 처리하며 최종 PCM 출력 순서와 일치시킨다. 클립·버스 compressor와 limiter는 공통 dB transfer 함수와 같은 curve를 사용한다.
- 프로그램 모니터의 L/R 미터는 미디어 파형 평균을 대신 표시하지 않는다. 공유 master의 soft clip 직전 stereo 합산점과 처리 후 출력점에 실제 `AnalyserNode` tap을 두고, 처리 후 L/R peak를 -60~0 dBFS 눈금으로 표시하며 soft clip 직전 peak가 1.0 이상이면 1.5초 과부하 hold를 남긴다. tap 출력은 0 gain sink로만 연결해 가청 신호를 중복 합산하지 않는다.
- 네 역할 버스의 게인·뮤트·솔로·리미터·전체 삽입 체인과 ADR 큐 길이·카운트다운·선호 마이크 이름을 팀 템플릿으로 로컬 저장하고 `.cutline-audio.json`으로 공유·가져오기하며, 다른 프로젝트에 한 번의 Undo 가능한 버스 변경으로 적용
- 마이크 장치 선택·입력 레벨·3초 카운트다운·일시정지/재개, 대사 큐와 다중 테이크 녹음·미리듣기·채택을 제공하고, 선택 파일을 데스크톱 앱 데이터에 영속 저장한 뒤 재생 헤드의 `대화` 오디오 클립으로 자동 배치하는 로컬 ADR·보이스오버
- 시퀀스별 ADR 대본 큐의 인·아웃 구간과 상태를 프로젝트에 저장하고 모든 녹음 원본을 별도 타임라인 레인에 보존하며, 큐 목록에서 채택 테이크 전환·구간 반복 재생·원본 포함 삭제를 수행하는 ADR 세션 관리. 일반 미디어 제거는 전체 시퀀스 클립과 ADR 테이크 참조를 모두 차단하고, 큐 삭제는 다른 클립·큐가 재사용하는 녹음 자산·디스크 원본·프록시를 보존하며 전용 원본만 삭제

### 출력

- 출력 모드와 같은 PQ/HLG transfer·BT.2020 primaries의 `I420P10` 원본이 출력 해상도와 정확히 같고, 해당 프레임에 변형·색상·효과·전환·조정 레이어·자막·복수 레이어가 없으면 디코더의 원시 10-bit 평면을 새 타임스탬프로 복사해 Canvas/WebGPU SDR 변환을 우회하는 네이티브 HDR straight-cut 경로

- 복수 PQ/HLG `I420P10` 영상 레이어는 WebGPU `RGBA16F` ping-pong 작업 버퍼에서 BT.2020 선형 광으로 합성한다. 위치·크기·회전·불투명도뿐 아니라 노출·대비·채도·색온도·틴트·하이라이트·섀도·Hue/Vibrance/Fade·Lift/Gamma/Gain·3구간 톤, 크롭·비네트와 Normal/Multiply/Screen/Overlay/Darken/Lighten 합성을 raw HDR 정밀도로 처리한다. ellipse/rounded/polygon/Bezier의 최대 8개 add/subtract/intersect 마스크, 반전·불투명도·페더는 알파만 8-bit mask texture로 전달하고 HDR RGB는 RGBA16F에 유지한다. chroma key는 PQ/HLG 역함수 전에 인코딩 RGB에서 키 색상·허용값·softness를 판정하고 spill 경계만 무채색화한다. 이미지·비 HDR 영상·모션 그래픽·자막은 투명 레이어 단위로만 Canvas에서 그린 뒤 Rec.709→BT.2020과 PQ 203-nit reference white/HLG 75% diffuse white 기준으로 같은 선형 버퍼에 얹어, 아래 HDR 원본의 하이라이트와 10-bit 정밀도를 유지한다.

### 로컬 협업과 정리

- 폴더·태그·메모와 이름/코덱/방향/해상도/얼굴/VFR 진단을 함께 찾는 미디어 검색
- 프로젝트에 저장되는 타임코드 검토 코멘트, 열림/해결 상태, 작성자, CSV 전달
- 프로젝트·시퀀스 식별자와 코멘트 ID를 포함한 `.cutline-review.json` 휴대 패키지 내보내기/가져오기, 동일 ID 변경 갱신과 시간·작성자·내용·상태 중복 제거를 적용하는 오프라인 검토 병합
- 데스크톱에서 완성 MP4를 선택하면 임의 로컬 포트와 128-bit 검토 토큰으로 같은 네트워크 전용 브라우저 링크를 열고, HTTP Range 요청으로 영상을 편집자 컴퓨터에서 직접 스트리밍하는 업로드 없는 LAN 검토 세션
- 검토자는 별도 앱·계정 없이 모바일/PC 브라우저에서 현재 재생 시점에 코멘트를 추가·수정·해결하며, 편집 앱은 3초 간격으로 ID와 ISO 수정 시각을 병합한다. 편집자 삭제는 동기화 경합에도 다시 나타나지 않도록 삭제 ID를 확인 응답까지 유지하며, 세션 종료 또는 앱 종료 시 링크가 닫힌다.
- 자동 저장 이력을 현재 프로젝트와 비교해 미디어·시퀀스 추가/삭제, 변경 시퀀스, 클립 수와 코멘트 차이를 표시하고, 전체 복원 외에 선택한 과거 시퀀스를 현재 작업을 덮어쓰지 않는 새 분기로 가져오기
- 버전 분기 시 source/nested 의존 시퀀스를 재귀 수집하고 시퀀스·트랙·클립·ADR 큐/테이크/컴프 ID를 새로 발급해 내부 참조를 함께 재작성하며, 현재 프로젝트에 없는 원본 미디어 항목만 병합
- 동일 프로젝트의 공통 자동 저장 체크포인트, 현재 편집본, 상대 `.cutline.json`을 비교하는 3-way 공동 작업 병합. 시퀀스 안에서 ID가 다른 추가·삭제와 서로 다른 클립/대본/제안/마커 변경은 자동 결합하고, 같은 ID를 양쪽에서 다르게 수정한 경우 현재 작업을 유지한 채 상대 시퀀스와 source/nested·ADR 의존성을 새 ID의 `병합 충돌 (상대)` 분기로 보존한다.
- 같은 클립 충돌은 현재 시퀀스에 열림 상태의 `Cutline 병합` 검토 마커를 생성하고 Delivery Guard가 미해결 개수를 납품 경고로 표시한다. 적용 전 자동 반영·충돌·분기 수와 공통 기준 확인을 다시 표시하며, 프로젝트 ID 불일치, 중복 stable ID 또는 존재하지 않는 트랙을 참조하는 클립이 있으면 변경 전에 병합을 거부한다.
- 병합 세션은 기준/상대 시각, 상대 프로젝트 이름, 충돌 종류·원본/상대 분기 entity ID, 현재/상대 값과 삭제 상태, 현재 클립·트랙 보존 사본, 상태와 결정 시각을 프로젝트 및 자동 저장에 최대 20건 보존한다. 버전 기록에서 현재 위치와 상대 분기로 이동하고 시퀀스 메타, 트랙, 클립, 대본, 편집 제안, 마커, 오디오 버스, ADR 큐, 교정 사전·학습 프로필별 `현재 유지` 또는 `상대 적용/삭제`를 결정하며 해결 기록에서도 결정을 다시 전환할 수 있다.
- 상대 클립 적용은 충돌 분기의 새 ID nested/ADR/group/link 참조를 그대로 사용하고 원본 clip ID만 복구해 현재 대상 트랙에 놓는다. 상대 트랙 종류가 현재와 다르면 별도 병합 트랙을 만들어 양쪽 내용을 보존한다. 미디어 현재/상대 결정은 파일을 복사·삭제하지 않고 프로젝트 메타데이터만 선택한다. 이름·종류·확장자·크기·길이가 같은 미디어는 현재 장비의 열린 File/Object URL·프록시·로컬 경로를 보존하고, 다른 미디어는 오프라인으로 전환해 상대 경로 자동 연결 또는 수동 재연결을 요구한다. 클립이나 ADR 테이크가 참조 중인 미디어 삭제는 차단한다. 시퀀스 전체 삭제/수정 충돌은 의존 시퀀스를 자동 교체하지 않고 상대 분기 확인 뒤 현재 상태로 닫는다. 세션의 모든 결정을 마치면 상대 분기는 삭제하지 않고 `병합 기록 (해결됨)` 감사 분기로 이름을 바꾼다.
- 사용자 모션·속도·팀 오디오·사용자 출력 프리셋을 하나의 `.cutline-pack.json`으로 묶어 공유·설치하는 Creator Pack. JSON 2MB, 범주별 개수와 값 범위를 검증하고 새 ID로 인스턴스화하며 이름+설정 지문이 같은 내용은 중복 설치하지 않는다.
- Creator Pack manifest는 실행 코드·네트워크·파일시스템 권한이 모두 `false`인 선언형 설정만 허용하고 하나라도 권한을 요구하면 설치를 거부한다. 설치 뒤 열린 인스펙터·오디오 믹서·출력 창의 템플릿 목록을 이벤트로 즉시 갱신한다.
- React 경계 오류뿐 아니라 전역 script error와 처리되지 않은 Promise rejection을 최대 10개 로컬 큐에 기록하고 5초 중복 억제, 문자열 길이 제한, 앱 재시작 후 재전송, 30초~24시간 지수 backoff를 적용하는 충돌 리포트 파이프라인
- 충돌 리포트는 사용자가 명시적으로 동의하고 HTTPS(또는 localhost) 운영 endpoint가 설정된 경우에만 `cutline-crash-v1`으로 전송한다. 성공 응답 뒤 로컬 큐에서 제거하며 로컬/네트워크 경로·URL query·이메일·UUID·따옴표 안의 동적 값을 로컬 적재와 전송 전에 제거한다. 미디어·프로젝트·렌더 설정은 payload 스키마에 포함하지 않으며 사용자는 큐를 JSON으로 직접 저장할 수 있다.
- 무의존성 Node 충돌 수집 서비스는 엄격한 스키마·32KB 요청 상한·origin 허용 목록·IP별 속도 제한·리포트 ID 중복 제거·단일 쓰기 큐·날짜별 JSONL·30일/512MB 보존 한도·정상 종료 drain을 적용한다. 서버도 같은 민감 정보 제거를 반복하고 IP·쿠키·요청 헤더를 저장하지 않으며 Docker 비루트 배포와 `/healthz`를 제공한다.
- 데스크톱 프로젝트 파일 옆에 숨김 `.cutline-lock` JSON을 `create_new`로 원자 생성하고 사용자·장비·process ID·획득/heartbeat 시각을 기록하는 공유 폴더 프로젝트 잠금. 15초 heartbeat와 45초 만료 판정을 사용하며 같은 인스턴스만 갱신·해제한다.
- 활성 또는 만료/손상 잠금이 있으면 소유자를 표시하고 사용자 확인 없이는 프로젝트를 열거나 덮어쓰지 않는다. 강제 인수된 기존 편집자는 다음 heartbeat에서 잠금 상실을 감지해 현재 경로 저장을 중단하고 다른 이름 저장을 안내한다.

## 남은 제품 개발

### 편집 기능

- PQ/HLG 10-bit 입력부터 WebGPU 선형 BT.2020 작업 버퍼 안에서 단일/복수 raw I420P10 영상의 공간 변형·기본 그레이딩·기본 Look/LUT·Master/R/G/B 사용자 곡선·HSL Qualifier·최대 16개 Primary/Curves/Qualifier/Look/Tone Map 색상 노드 DAG·크롭·비네트·블러·그림자·추적 얼굴 모자이크·합성 모드·다중 자유 마스크·크로마키·검정 디졸브, 이미지·자막 레이어 합성과 색상/블러/노드 조정 레이어를 처리하는 소스 구현을 완료했다. 남은 게이트는 사용자 GPU·HEVC Main10 장비에서 SDR 미리보기와 HDR 출력의 의도 일치 및 휘도·10-bit 보존 비교다.
- 역재생·정방향 가변 속도 오디오의 부분 PCM 디코딩, 상관 정렬 granular pitch-preserving time stretch와 rolling AudioContext scheduling 소스는 구현했다. 남은 게이트는 긴 GOP/고배속/가변 속도 실제 원본에서 decoder가 250ms 청크와 0.9초 예약 여유를 유지하는지, 25~400% 대사·음악의 음정과 transient, 탐색·루프·렌더 청크 경계의 click/gap이 최종 PCM과 같은지 사용자 장비에서 비교하는 일이다.

### 전문 후반 작업

- RGBA16F 다중 레이어 합성기, 기본 그레이딩·기본 Look/LUT·256단계 사용자 곡선·HSL Qualifier·최대 16개 노드의 다중 입력 DAG·블러·그림자·추적 얼굴 모자이크·다중 자유 마스크·크로마키·색상/블러/노드 조정 레이어와 raw I420P10 입력/출력은 구현되어 있다. PQ/HLG·BT.2020-NCL limited-range I420P10이 아닌 입력, 회전 메타데이터가 있는 원본과 별도 흰색 전환 표현은 해당 레이어만 Canvas 대체 경로를 쓰며 아래 RGBA16F 프로그램은 유지한다. 이 경계 조합의 실제 납품 비교가 남아 있다.

### 운영·출시

- Windows/macOS 실제 장비의 장시간 VFR·HDR·전문 코덱 검증
- Windows 코드 서명 인증서와 macOS Developer ID 서명·공증 자격 증명 연결. 다운로드한 EXE/MSI의 Authenticode `Valid`·고정 Subject, DMG/PKG의 codesign/pkgutil·Gatekeeper·고정 Apple Team ID를 실행 전후 두 번 판정하는 네이티브 검증기는 구현되어 있다.
- 업데이트·충돌 수집 서비스의 실제 HTTPS 도메인·암호화 저장 볼륨 연결. 두 Node 서버 소스, 비루트 Docker/Caddy 자동 TLS 배포, 보존·전달 정책과 클라이언트 계약은 구현되어 있다. 업데이트 서버는 플랫폼별 매니페스트의 Ed25519·keyId와 실제 설치 파일 SHA-256·OS별 확장자·2GB 상한을 시작 시 확인하고 무압축 전체/Range 스트리밍만 제공한다. 업데이트 클라이언트의 HTTPS·64KB·무리다이렉트·URL 자격 증명 제한과 Windows/macOS Rust 네이티브·브라우저 WebCrypto의 고정 공개 키 검증도 구현되어 있다.
- 인터넷 외부망용 종단 간 암호화 검토 릴레이·영구 세션은 운영 서비스 이후 범위다. 서로 다른 편집자의 동일 시퀀스 클립 단위 3-way 병합과 공유 드라이브 프로젝트 파일의 사용자·장비 lock/heartbeat는 소스 구현했으며, 검토 링크는 업로드 없는 동일 LAN 범위다.
- 최신 소스의 MSI/NSIS/DMG 재빌드와 설치·제거·업데이트 검증

릴리스 CI는 태그의 `v<SemVer>` 또는 수동 입력 version을 `package.json`, `tauri.conf.json`, Cargo package에 동기화한다. `release/build-desktop.mjs`는 matrix의 `windows-x86_64`·`macos-aarch64` 대상과 channel을 사용해 플랫폼별 manifest URL을 만들고 Vite의 공개 키/keyId와 Rust의 고정 공개 키를 같은 환경에서 빌드한다. origin·키·keyId가 부분 설정되거나 crash endpoint가 자격 증명·query/hash를 포함하면 패키징 전에 실패한다.

현재 코드에는 `cutline-update-v1` 고정 canonical payload, OS·CPU platform 일치, 프런트엔드와 Rust 빌드에 함께 고정하는 Ed25519 공개 키·keyId 검증, HTTPS 전용 매니페스트·다운로드 URL 검증, `release/create-update-manifest.mjs` 채널 생성 도구와 `release/sign-update-manifest.mjs` 릴리스 서명 도구가 있다. `services/update-server`는 개인 키 없이 공개 키로 stable/beta·플랫폼별 catalog와 실제 artifact 해시를 검증한 뒤 매니페스트 no-store, 설치 파일 immutable·Range·동시 다운로드 한도로 제공한다. 데스크톱은 서명 payload의 URL·필수 SHA-256을 Rust에서 다시 검증해 사용자가 고른 경로의 `.part`로 최대 2GB를 받고, 해시·Windows Authenticode 또는 macOS Developer ID/Gatekeeper·고정 게시자 일치 뒤 원자 이동·30분 1회 토큰·실행 직전 재검증·두 번째 사용자 확인을 거쳐 설치 파일을 연다. 이전/목표 버전과 검증 파일을 7일 보존하고 다음 프로세스에서 적용 성공을 판정하며, 실패·취소 시 기존 파일을 전부 재검증해 재시도한다. 무인 자동 교체·자동 롤백은 Tauri updater용 별도 서명 키·`.sig`와 서명 패키징 자격 증명이 준비되기 전까지 활성화하지 않는다.

충돌 보고 운영 코드는 `services/crash-collector`에 있으며 인터넷에는 직접 포트를 노출하지 않고 HTTPS reverse proxy 뒤에 배치한다. 앱은 설치된 데스크톱 버전, runtime과 정제된 오류 진단만 전송하고 서버는 날짜별 JSONL을 운영자 전용 볼륨에 저장한다. 출시 게이트로 남은 것은 실제 도메인·TLS·볼륨 접근 제어·백업 보존 정책을 배포 환경에 적용하고 동의/비동의 양쪽 흐름을 사용자 장비에서 확인하는 일이다.

## 사용자 검증 순서

1. MP4/MOV 파일을 드롭하고 가져오기 버튼으로 각각 등록한다.
2. 타임라인 추가·이동·트림·분할 후 미리보기에서 컷과 오디오를 확인한다.
3. 시퀀스 이름 변경·복제 후 원본과 복제본을 각각 편집하고, 중첩/쇼츠/병합/렌더 참조가 있는 시퀀스의 삭제가 차단되는지 확인한다.
4. 프로젝트 저장 후 앱을 다시 열어 시퀀스 목록과 원본이 자동 연결되는지 확인한다.
5. 색보정·크롭·마스크·블러·모자이크·조정 레이어를 미리보기와 MP4에서 비교한다.
6. SRT/VTT와 Whisper 자막, 9:16/4:5/1:1 파생 시퀀스를 확인한다.
7. 10분 이상 프로젝트를 직접 파일 스트리밍으로 출력한다.
8. 발견 문제를 `troubleshooting.md`에 누적하고 수정 후 같은 항목을 다시 확인한다.
