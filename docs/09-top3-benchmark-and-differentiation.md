# 09. Top 3 벤치마크와 Cutline 차별화

## 목적

Cutline은 Premiere Pro, DaVinci Resolve, CapCut Desktop을 유튜브 롱폼·쇼츠 제작의 기준 제품으로 삼는다. 제품 전체를 화면 단위로 복제하지 않고, 세 제품에서 실제 납품에 필요한 기능 범주를 빠짐없이 정의한 뒤 Cutline의 더 짧고 복구 가능한 작업 흐름으로 다시 설계한다.

기준 자료는 2026-08-09에 확인한 공식 제품 설명이다.

- [Adobe Premiere 기능](https://www.adobe.com/products/premiere/features.html): 정밀 트림, 3점 편집, 텍스트 기반 편집, 멀티캠, 마스크·추적, 색 관리, 오디오 정리와 출력
- [DaVinci Resolve 제품 기능](https://www.blackmagicdesign.com/products/davinciresolve): Edit/Cut, Fusion, Color, Fairlight, 미디어 관리, AI 추적과 Deliver
- [CapCut Desktop 기능](https://www.capcut.com/tools/desktop-video-editor): 멀티트랙, 키프레임·그래프, 색상 휠, 자동 자막, 자동 리프레임, 스마트 검색과 크리에이터용 빠른 출력

여기서 “Top 3 기능을 모두 가진다”는 것은 세 제품의 상표·화면·유료 자산을 복제한다는 뜻이 아니다. 미디어 관리, 정밀 편집, 합성, 색상, 오디오, 자막, AI 보조, 롱폼·쇼츠 파생, 출력, 복구, 협업이라는 실무 작업 범주마다 동등하거나 더 짧은 완료 경로를 제공한다는 제품 완료 조건이다. 생성형 모델, 스톡 자산 수, 방송 하드웨어 제어처럼 외부 라이선스·서비스에 종속된 항목은 호환 확장점으로 분리한다.

## GUI 기준

- 기본 뼈대는 유튜브 편집자에게 익숙한 Premiere 계열의 `미디어/소스 + 프로그램 + 타임라인 + 인스펙터` 배치를 사용한다.
- Color·Audio·Fusion급 작업은 Resolve처럼 필요할 때 확장되는 전문 화면을 제공하되, 기본 컷 편집 중에도 자주 쓰는 값은 인스펙터에서 바로 바꿀 수 있게 한다.
- 자동 자막, 롱폼→쇼츠, 템플릿, 빠른 출력은 CapCut처럼 시작점을 짧게 두되 적용 전 비교, 세부 수동 수정, Undo와 원본 추적을 반드시 제공한다.
- 제품 고유의 패널 명칭·아이콘·색상·단축키를 사용하며 경쟁 제품 UI를 픽셀 단위로 복제하지 않는다.

## 경쟁 우위가 되는 하나의 작업 흐름

`원본 한 번 가져오기 → 대본 기반 초벌 → 정밀 타임라인 편집 → 색상·오디오 후반 → 본편·쇼츠 동시 파생 → Delivery Guard → 복구 가능한 렌더 큐 → 검토 패키지 병합`을 프로젝트 안에서 끊김 없이 끝내는 것이 Cutline의 중심 경험이다.

이 흐름의 차별점은 다음과 같다.

1. AI 결과마다 이유·입력 범위·처리 위치·변경 범위를 보여주며 자동 적용하지 않는다.
2. 본편과 쇼츠를 별도 복사본으로 방치하지 않고 Creator Source Graph로 변경 영향을 추적한다.
3. 초보용 빠른 조작과 전문 노드·버스·스코프가 같은 미리보기/출력 계산 경로를 사용한다.
4. 자동 저장, 미디어 재연결, 영속 프록시, 렌더 기록을 부가기능이 아닌 편집 모델의 기본 계약으로 둔다.
5. 클라우드와 ComfyUI는 선택이며 핵심 편집·전사·분석은 로컬 우선으로 유지한다.

## 불편함을 줄이는 설계 원칙

1. **작업 공간을 옮기지 않아도 된다.** 컷, 자막, 색상, 오디오의 자주 쓰는 조작은 선택한 클립의 인스펙터에 나타나며 전문 화면은 필요할 때만 연다.
2. **AI가 타임라인을 몰래 바꾸지 않는다.** 모든 AI 결과는 제안, 미리보기, 적용, 되돌리기 단계를 가진다.
3. **롱폼과 쇼츠를 따로 복사하지 않는다.** 파생 시퀀스가 원본 구간을 참조하고 사용자가 동기화 범위를 선택한다.
4. **내보내기를 시작하기 전에 실패 원인을 보여준다.** 오프라인 미디어, 지원하지 않는 코덱, 빈 구간, 클리핑, 자막 안전 영역을 사전 검사한다.
5. **프로젝트는 항상 복구 가능해야 한다.** 자동 저장 이력, 원본 재연결, 영속 프록시, 렌더 작업 기록을 기본 기능으로 둔다.
6. **클라우드는 선택이다.** 기본 편집·전사·분석은 로컬에서 동작하며 외부 전송 기능은 데이터 범위와 목적을 먼저 표시한다.
7. **외부 AI는 이중 확인한다.** 전체 AI 데이터 설정에서 기능별 처리 위치·입력·보관을 확인하고, 선택적 ComfyUI 전송은 실제 실행 창에서도 동의가 켜져 있어야 동작한다.

## Cutline 고유 기능

### Creator Source Graph

하나의 롱폼 시퀀스를 원본으로 영상 본편, 티저, 9:16·4:5·1:1 쇼츠, 자막 파일과 썸네일 후보를 연결한다. 파생물마다 어느 원본 구간과 자막 문장을 사용했는지 추적하고, 원본 수정 시 영향을 받은 결과물만 알려준다.

### Transcript Edit Contract

대본 삭제가 즉시 원본을 파괴하지 않는다. Cutline은 제거 후보와 타임라인 영향, 문장 연결부의 오디오 상태를 먼저 보여주고 승인된 변경을 컷·자막·마커에 원자적으로 적용한다.

### Delivery Guard

YouTube 납품 전에 해상도, 프레임레이트, 코덱, 피크·러드니스, 자막 안전 영역, 오프라인 원본과 예상 파일 크기를 검사하고 수정 가능한 항목은 한 화면에서 해결한다.

### Recovery-first Render

렌더 작업과 출력 위치를 프로젝트와 별도로 기록한다. 여러 시퀀스와 쇼츠 묶음을 먼저 예약하고 한 출력 폴더에서 자동 순차 처리하며, 일시정지·취소·재시도와 실패 원인을 남긴다. 장시간 영상은 30초 단위 완결 MP4 체크포인트로 앱 캐시에 직접 기록하고 앱 재실행 뒤 미완료 구간부터 계속한 다음, 인코딩 패킷을 재압축 없이 하나의 최종 MP4로 결합한다. 쇼츠 묶음은 완료 파일 단위로 재개한다.

## 2026-08-09 구현 스냅샷

- D1 편집 코어: 소스 I/O·3점 삽입, 선택 트랙과 독립된 시퀀스별 단일 V/A/T source patch 대상과 전체 해제 차단, J/L 컷 기반 오디오 분리, 슬라이드 트림, cubic Bézier 제어점과 JSON 팀 프리셋을 포함한 적분형 속도 램프, 중첩 경계 전환·순환 진단·사용자 합성 우선순위·부모/자식 속도 램프 완전 재매핑, FFprobe 컨테이너 TC/릴 자동 추출과 미설치 시 원시 태그·QuickTime `tmcd` 자체 대체 판독·드롭프레임 계산·FFmpeg 프록시 TC 대조, 파형/클랩/TC 동기화 멀티캠과 각도 라이브 컷, 단축키 편집기, 시퀀스 이름 변경·내부 stable ID 재발급 복제·중첩/파생/병합/렌더 참조 보호 삭제, 영속 자동 순차 렌더 큐, 30초 완결 MP4 체크포인트 기반 앱 재실행 후 재개와 무재인코딩 패킷 결합, 쇼츠 완료 파일 단위 재개, Delivery Guard까지 소스 구현을 완료했다.

- D4 협업과 생태계: 로컬 타임코드 코멘트·해결 상태·CSV 전달, ID 기반 변경 갱신과 내용 중복 제거를 제공하는 휴대형 검토 패키지 병합에 더해, 완성 MP4를 클라우드에 올리지 않고 편집자 PC가 HTTP Range로 직접 제공하는 토큰형 LAN 검토 링크를 구현했다. 검토자는 계정 없는 브라우저에서 재생 시점 코멘트를 남기고 편집 타임라인과 3초 양방향 병합한다. 자동 저장 버전은 미디어·시퀀스·클립·코멘트 차이를 비교하고 선택 시퀀스와 nested/source·ADR 의존성을 새 ID 분기로 안전하게 가져온다. 공통 체크포인트를 기준으로 현재/상대 프로젝트를 3-way 비교해 서로 다른 변경은 자동 결합하고 같은 ID 충돌은 현재 작업을 유지한 채 상대 전체를 새 ID 분기와 검토 마커로 보존한다. 병합 세션과 양쪽 값은 프로젝트에 영속되며 버전 기록에서 시퀀스 설정·트랙·클립·대본·제안·마커·오디오 버스·ADR·미디어·사용자 사전별 현재/상대/삭제 결정을 수행하고 해결된 상대 분기를 감사 기록으로 남긴다. 미디어 결정은 로컬 파일을 덮어쓰지 않으며 같은 원본의 현재 장비 핸들을 유지하고 다른 원본은 오프라인 재연결로 전환한다. 참조 중인 미디어 삭제와 시퀀스 전체 삭제/수정처럼 의존성 자동 교체가 안전하지 않은 결정은 차단하거나 분기 확인을 요구한다. 공유 드라이브 프로젝트는 원자 lock·사용자/장비 소유권·15초 heartbeat·명시적 인수로 동시 저장을 차단한다. 모션·속도·오디오·출력 설정은 코드/네트워크/파일 권한이 없는 선언형 Creator Pack으로 묶어 공유한다. 계정형 인터넷 외부망 검토 링크와 실시간 공동 편집은 운영 릴레이 이후 범위다.
- 위 항목은 코드 구현 상태이며 사용자 장비 검증과 서명된 배포 완료를 뜻하지 않는다.

## 개발 순서

### D1 — 편집 코어 완성

- 중첩 시퀀스의 생성·내부 편집·재귀 합성
- 소스 모니터 인·아웃과 3점 편집, J/L 컷
- 멀티캠 동기화·라이브 컷, 클립 동기화
- 키보드 단축키 편집기, 슬라이드 트림, 트랙 대상 지정
- 키프레임 속도 램프와 영상·오디오 공통 소스 시간 매핑
- 렌더 큐와 납품 전 검사

완료 조건: 마우스와 단축키 양쪽으로 30분 유튜브 프로젝트를 구성하고 저장·재열기·출력할 수 있다.

### D2 — 전문 후반 작업

- 색상 휠·커브·스코프·세컨더리·추적 마스크·HDR 관리
- 파라메트릭 EQ·컴프레서·리미터·버스·러드니스 미터
- 자유형 베지어 마스크, 페더, 모션 추적, 크로마키
- 모션 그래프 편집기와 재사용 가능한 타이틀·효과 템플릿

완료 조건: 색상·오디오·합성 결과가 미리보기와 최종 파일에서 일치하고 전문 측정값을 프로젝트에 보존한다.

### D3 — 크리에이터 인텔리전스

- 화자 분리, 의미 검색, 장면·인물·B-roll 검색
- 롱폼 변경을 쇼츠 파생물에 선택적으로 재반영
- 무음·말버릇·반복 제거 전 연결부 미리듣기
- 채널별 자막·색상·오디오·출력 규칙 프리셋

완료 조건: AI 없이 모든 결과를 수동 수정할 수 있고, AI 변경은 적용 전후와 처리 위치가 기록된다.

### D4 — 협업과 생태계

- 리뷰 링크, 타임코드 코멘트, 버전 비교·병합
- 공유 폴더 프로젝트 lock/heartbeat와 소유자 표시, 공통 체크포인트 기반 동일 시퀀스 클립 단위 3-way 병합을 구현했다. 원격 프록시 캐시 주소·클립 단위 checkout과 실시간 공동 편집은 운영 팀 저장소 이후 범위다.
- 안전한 효과·내보내기 확장 API: 1차로 실행 코드를 받지 않는 Creator Pack manifest와 모션·속도·오디오·출력 스키마를 구현했으며, 네이티브 코드형 플러그인은 별도 서명·샌드박스 설계 전까지 허용하지 않는다.
- Windows/macOS OS 코드 서명·공증, Tauri 무인 교체·롤백용 `.sig`와 실제 배포 도메인. 고정 공개 키 Ed25519 매니페스트 검증과 서명 payload 기반 네이티브 다운로드·SHA-256 재검증·1회 실행 토큰, 릴리스 생성·서명 도구를 구현했다. 공개 키로 stable/beta 플랫폼별 catalog와 artifact 해시를 검증하고 무압축 Range 스트리밍하는 Node/Docker 업데이트 서버도 구현했다. 동의형 충돌 로컬 큐·재시도와 스키마 검증·속도 제한·중복 제거·보존 한도를 가진 수집 서버도 있으며 실제 TLS·운영 볼륨 연결이 남아 있다.

완료 조건: 서로 다른 두 장비에서 프로젝트를 주고받아 미디어 재연결과 버전 충돌을 해결하고 서명된 설치 파일로 업데이트할 수 있다.

## 범위 경계

- ComfyUI는 필수 편집 기능이 아니다. 설치나 실행을 요구하지 않는 선택적 외부 생성·보정 연동으로만 유지한다.
- 스톡·음악 마켓과 특정 생성 모델은 핵심 편집기와 분리한다.
- 경쟁 제품의 명칭, 자산, UI를 복제하지 않는다. 기능 범주와 검증 가능한 결과만 벤치마킹한다.
- 구현 여부는 화면 존재가 아니라 실제 미디어 입력→편집→저장→재열기→출력 흐름으로 판단한다.
